## Overview

원화 충전, 회원 간 송금, 외화 환전, 가맹점 결제를 하나의 지갑에서 제공하는 5인 팀 프로젝트입니다.
응답이 유실되거나 거래가 동시에 몰려도 잔액과 거래 상태가 어긋나지 않도록, 모든 자금 이동을 **공용 원장에 한 번만** 기록하고 결과를 모르는 거래는 다시 처리해 확정합니다. 끝내 확정하지 못한 거래는 대사와 운영자 보정으로 마무리합니다.

저는 **프론트엔드 전체와 송금**(API · 상태 관리 · 멱등성 · 동시성 · 장애 대응)을 맡았습니다. 팀 프로젝트가 끝난 뒤에는 개인 저장소에서 **송금 완료 알림**(Outbox → Kafka → 화면 알림 · Slack)을 이어서 개발하고 있습니다.

- 백엔드: [gajigaji04/travelpay](https://github.com/gajigaji04/travelpay) (팀 저장소 [dont-worrys/travelpay](https://github.com/dont-worrys/travelpay) 에서 이어 개발)
- 프론트엔드: [dont-worrys/travelpay-front](https://github.com/dont-worrys/travelpay-front)

## 주요 기능

- **사용자 · 인증** — Redis 세션 인증, CSRF 보호, 로그인 시도 제한, 관리자 회원 관리 · 세션 강제 종료
- **지갑 · 충전** — 통화별 지갑, 은행 계좌에서 원화 충전(실패 시 환불), 충전 대사 · 관리자 보정
- **송금** — 회원 간 통화별 송금, 상대방 마스킹 이름 표시, 송금 완료 화면 알림 · Slack 알림
- **환전 · 환율** — 견적 기반 환전, 목표 환율 도달 시 자동 체결되는 예약 환전
- **결제 · 정산** — 가맹점 결제, 부분 환불, 판매 대금 정산
- **원장** — 모든 자금 이동을 복식부기(차변 · 대변)로 기록하는 공용 원장

## Technical Details

제가 맡은 부분 위주로 정리했습니다.

- **중복 송금 방지** — `Idempotency-Key`, DB UNIQUE 제약, 저장된 요청 값 비교로 같은 송금이 두 번 처리되지 않게 했습니다.
- **동시 송금** — 비관적 잠금, 계정 ID 기준 잠금 순서 고정, DB 잔액 제약으로 교착과 초과 출금을 막았습니다.
- **결과 불명 처리** — 원장 타임아웃 · 5xx 는 실패로 단정하지 않고 PROCESSING 으로 둔 뒤 같은 reference 로 복구합니다. 재시도 5회를 넘으면 MANUAL_REVIEW 로 넘겨 원장 거래와 대조해 확정합니다.
- **프론트엔드 금전 요청** — 결과를 모르면 같은 키 · 같은 본문으로만 재요청하고 입력을 잠가 화면에서도 중복 거래가 생기지 않게 했습니다. Vite · React 19 · TypeScript, 모든 API 는 Gateway 를 거칩니다.
- **송금 완료 알림** — 송금 상태 변경과 같은 트랜잭션에 Outbox 를 기록해 Kafka 로 발행하고, user-service 가 eventId 로 중복을 걸러 보낸 · 받는 사람 화면 알림과 Slack 알림을 남깁니다. 알림은 송금 처리와 분리되어 Kafka 장애가 송금에 영향을 주지 않습니다.
