## Overview

단기 심화 온보딩 주차 과제로 시작한 미니 배달 서비스입니다. 과제 범위(회원 · 메뉴 · 주문 · 결제)를 마친 뒤, 이슈 단위로 **수수료 · 일 정산 · 환불 · 이월 · 정산 감사 이력 · 재집계**와 Redis · Kafka 기반 비동기 처리까지 확장했습니다.
"동작하는 기능"을 넘어 **중복 결제, 동시 요청, 장애 상황에서도 데이터가 어긋나지 않게** 만드는 것을 목표로 했습니다.

## 주요 기능

- **회원 · 인증** — JWT 인증, 역할 3종 기반 권한 분리(Spring Security)
- **매장 · 메뉴 · 주문 · 결제** — 주문 상태 전이와 수수료 규칙을 엔티티에 두고 서비스에서 조합
- **정산** — 스케줄러 기반 일 정산 집계, 환불 반영 · 이월, 정산 상태 변경 이력, 관리자 재집계
- **이벤트 발행 · 알림** — Transactional Outbox → Kafka, 소비 실패 시 DLT 재처리
- **운영** — Flyway 마이그레이션(V1~V14), 데이터 보관 기간 정리, TraceId 로깅, Prometheus · Grafana 모니터링, springdoc OpenAPI 문서

## Technical Details

- **결제 멱등성** — `Idempotency-Key` 로 첫 응답을 재전송합니다(같은 키에 다른 요청 422, 처리 중 409, Redis 장애 시 503). 중복 결제 차단 자체는 DB 가 맡도록 주문 행 잠금과 `payments.order_id` UNIQUE 제약을 두었고, 멱등 기록을 결제와 **같은 트랜잭션**에 DB 로도 저장해 Redis 기록이 사라져도 재전송할 수 있게 했습니다.
- **Redis 분산 락** — `SET NX PX` 로 획득하고, Lua 스크립트로 **토큰이 일치할 때만 해제**합니다. Redis 장애 시에는 실행을 건너뛰고 실패 메트릭을 남깁니다.
- **Transactional Outbox** — `FOR UPDATE ... SKIP LOCKED` 로 여러 인스턴스가 같은 이벤트를 중복 발행하지 않게 하고, 같은 주문의 앞선 이벤트가 대기 중이면 뒤 이벤트를 막아 **주문 단위 순서를 보장**합니다(메시지 키 = 주문 ID). 실패 시 지수 백오프 후 FAILED 처리, Consumer 는 eventId 로 중복을 제거합니다.
- **keyset 페이징** — offset 대신 `(store_id, id)` 인덱스를 타는 keyset 방식으로 깊은 페이지 조회를 개선했습니다.
- **테스트** — 단위 · 통합 테스트 약 70개 클래스. Testcontainers(PostgreSQL · Kafka)로 실제 인프라에 가깝게 검증하고, 결제 · 수수료율 변경 동시성 통합 테스트를 둡니다. GitHub Actions 에서 `./gradlew build` 로 실행합니다.
- **부하 측정** — k6 스크립트로 목록 API 를 측정하고 결과를 문서로 남겼습니다.
