## Overview

단기 심화 온보딩 주차 과제로 시작한 미니 배달 서비스입니다. 과제 범위(회원 · 메뉴 · 주문 · 결제)를 마친 뒤, 이슈 단위로 **수수료 · 일 정산 · 환불 · 이월 · 정산 감사 이력 · 재집계**, Redis · Kafka 기반 비동기 처리, **토스페이먼츠 결제 연동**, 사장님 **실시간 주문 알림**, 고객 · 사장님 · 관리자 **웹 화면**까지 확장했습니다.
돈이 오가는 흐름(결제 → 정산 → 환불)에서 **중복 · 유실 없이 기록을 맞추는 것**을 목표로 했습니다.

## 주요 기능

- **회원 · 인증** — JWT(Access 15분) + Refresh Token(HttpOnly 쿠키, 재발급마다 교체 · 재사용 감지 시 전체 폐기), 카카오 · 구글 소셜 로그인, 고객 → 사장님 전환 신청과 관리자 승인
- **매장 · 메뉴 · 주문** — 주문 당시 메뉴 이름 · 단가 스냅샷, 상태 전이(결제 → 수락 → 배달완료), 배송 주소 검증
- **결제** — 토스페이먼츠 결제창 연동(테스트 모드), 전액 · 부분 환불, 토스 없이 장애를 재현하는 가짜 PG 모드
- **정산** — 배달완료 기준 일 정산, 관리자 확정 → 지급, 환불은 다음 정산에서 차감 · 이월, 감사 이력과 누락분 재집계
- **이벤트 · 알림** — Transactional Outbox → Kafka, 멱등 Consumer, DLT 재처리 CLI, 사장님 화면 SSE 실시간 주문 알림
- **화면** — React 19 · TypeScript 로 만든 랜딩 · 고객 주문 · 사장님 주문 처리 · 정산 화면 (Vercel 배포)
- **운영** — Flyway 마이그레이션, prod 프로필 필수 값 점검, TraceId 로깅, Prometheus · Grafana 대시보드와 알림 규칙

## Technical Details

- **PG 결제 결과 불명 처리** — 승인 · 취소가 시간 초과되면 실패로 단정하지 않고 조회 API 로 확인합니다. 그래도 모르면 503 을 돌려주고 화면은 결제창 대신 **같은 요청만** 재시도합니다. 토스 멱등 키와 결제 키 UNIQUE 로 승인은 한 번, 부분 취소는 재시도 전 잔액을 확인해 중복 환불을 막았습니다.
- **결제 멱등성** — `Idempotency-Key` 로 첫 응답을 재전송합니다(같은 키에 다른 요청 422, Redis 장애 시 503). 중복 결제 차단 자체는 DB UNIQUE 제약이 맡고, 멱등 기록을 결제와 **같은 트랜잭션**에 DB 로도 저장해 Redis 기록이 사라져도 재전송할 수 있게 했습니다.
- **정산** — 확정 · 지급된 기록은 고치지 않고 환불을 다음 정산에서 차감 · 이월합니다. 회계 항등식(지급액 = 판매 정산액 − 환불 정산액 + 미차감 이월분)을 테스트로 고정했습니다.
- **Transactional Outbox** — `FOR UPDATE ... SKIP LOCKED` 로 중복 발행을 막고 주문 단위 순서를 보장합니다. Kafka 가 멈춰도 결제는 성공하고 이벤트는 회복 후 발행됩니다.
- **keyset 페이징** — offset 대신 `(store_id, id)` 인덱스를 타는 keyset 방식으로 깊은 페이지 조회를 개선했습니다.
- **테스트** — 108개 클래스 946건. Testcontainers(PostgreSQL · Redis · Kafka)로 실제 인프라에 가깝게 검증하고, k6 부하 테스트와 Prometheus 알림 규칙 발동까지 확인했습니다.
